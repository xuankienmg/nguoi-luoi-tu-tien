# Tông Môn bản 1 — Kế hoạch triển khai

> Spec: `docs/superpowers/specs/2026-11-11-tong-mon-design.md`. Thực hiện inline trong session này.

**Mục tiêu:** Tông Môn (tạo/xin vào/duyệt/rời, chức vị, điểm danh + quyên góp, quỹ + cấp tông + buff tu luyện,
cửa hàng cống hiến, chat tông) chạy được ở mọi chế độ.

**Kiến trúc:** `ServerSect(GameDbContext)` giữ toàn bộ luật đụng bảng tông (UPDATE có điều kiện cho phần dùng chung).
`GameService.Sect.cs` bọc các hành động có trừ/cộng linh thạch, vật phẩm. API trả `SectActionResponse(state, message, kind, sect)`
để giao diện cập nhật trong một lượt. Buff đọc qua `SectBuff` (bộ đệm 60 giây, nạp ở `LoadAsync`).

## Các bước
1. Entity + DbContext + SchemaUpgrade + migration + SQL. Kiểm: `dotnet build`.
2. `SectData`, `SectBuff`, `ServerSect`, `GameService.Sect` — viết test `SectTests` trước cho từng luật
   (tạo, đơn/duyệt/tự duyệt, rời + 24h, giải tán, quyền, Tông chủ vắng, điểm danh/quyên, nâng cấp, cửa hàng, chat tách kênh, buff).
   Kiểm: `dotnet test test/GemSystemTests --filter "FullyQualifiedName~Sect"` và `~Chat`.
3. DTO + API + BodyAllowed. Kiểm: build + test `OnlineBoundary` liên quan.
4. UI: tab Tông Môn, tab chat tông; hàm thuần trong `sect.js` có test `node --test test/sect.test.cjs`.
5. i18n + ghi chú phát hành; chạy bản `--web`, thử luồng tạo → điểm danh → quyên → nâng cấp → mua → chat.
